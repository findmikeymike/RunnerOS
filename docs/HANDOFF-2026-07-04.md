## Shared Intel Awareness

Agents are aware of Shared Intel through central runtime context injection, not by hand-editing every individual agent prompt.

Flow:

1. User clicks `Share Intel` in a chat.
2. Renderer calls `sharedIntel:share` for the active workspace/session.
3. Backend reads recent session messages, extracts durable nuggets, and picks target workers from the active agent catalog.
4. Router saves or updates targeted workspace context docs using `routing: { mode: "targeted", agents: [...] }`.
5. When an agent launches, `loadActiveContextDocsForAgent` filters workspace context for that agent slug. Concierge/HNIC keeps its broad-context override.
6. `composeAgentSystemPrompt` and workflow prompt composition inject matching notes into a dedicated `Shared Intel for this worker:` section.
7. Shared Intel docs are excluded from the generic workspace-context block to avoid duplicated prompt bloat.

Practical meaning: specialist agents see only relevant shared nuggets; HNIC can see broad shared context; future agents automatically participate if they are in the active agent catalog and receive targeted context docs.

## HQ State Of Play / Proactive Routing

HQ State of Play is the action layer above Shared Intel.

Practical meaning:

```text
Shared Intel = what workers should know.
HQ State of Play = what Artist HQ should do next.
```

Flow:

1. Source context docs are saved or updated: Artist Profile, Spotify snapshot, Network, Calendar, Community, Artist Vault, Shared Intel, or user goals.
2. Server-side refresh builds a derived workspace context doc with slug `hq-state-of-play`.
3. The composer produces a deterministic `HqStateOfPlay` JSON payload inside the doc.
4. `nextMove` summarizes the best current move, why it matters, attention items, gaps, momentum, and goal progress.
5. `nextMove.route` adds a launch hint: target/manual, suggested agent, action, confidence, prompt, context doc slugs, and blocker reason.
6. Artist HQ Home parses the generated doc and shows a State of Play panel.
7. Proactive mode is stored per workspace in local storage.
8. `Start Route` is available only when the route is safe: proactive mode on, target agent active, no route blocker, and all requested context docs still exist and are enabled.

Important safety distinction:

- `contextDocSlugs` are workspace context docs, not external source/tool slugs.
- The parser accepts old generated JSON with `sourceSlugs` for compatibility, but new state writes `contextDocSlugs`.
- This feature does not auto-run background agents yet. It is user-controlled launch readiness.
- Do not build automatic execution before visually smoking the current `Start Route` path in Electron.
