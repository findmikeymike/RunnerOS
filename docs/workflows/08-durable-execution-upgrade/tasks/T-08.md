# T-08 — stable child execution and joins

Revision r10 · executable internal integration · P-03 remains open.

Persist deterministic child identity and frozen input/constraints before child execution. Bind parent run/slot, required/detached mode, cancellation/join policy, output schema, inherited principal/workspace/tools/deadline and root budget. Repeat launch attaches to the same child; callback loss never generates a replacement child.

Use a dedicated journal transaction to commit the stable parent edge, root reservations and child row atomically. Repeat admission must compare the entire frozen child contract. Do not widen legacy AgentMessageService's JSON-receipt path or claim it durable. Required joins consume only a committed validated child result, exactly once; order follows recorded slots. Parent completion must not bypass unresolved required children. Conservative root reservation covers the full child budget before launch and is retained for uncertain work. Detached policy is explicit; unsupported detachment/cancellation modes fail closed.

Ownership: child coordinator owner owns new server-core durable-child-runner/tests; journal owner owns atomic reservation/child edge and root budget additions. Integration lead verifies actual read-child execution and process-death boundaries.

Proof: real child read execution, restart before child launch and after child completion before join, exact replay, changed schema/input refusal, inherited constraints, cancellation propagation, late result no parent revival, required-child completion barrier. No model-facing delegation or legacy bridge activation until the specific seam has matching tests.

The host-owned startChild seam uses an active parent claim and the same read runner, so required requests and detached child execution participate in host shutdown. Default-factory Pi child recovery is tested through the actual subprocess with a loopback SSE provider; no public delegation tool is registered.
