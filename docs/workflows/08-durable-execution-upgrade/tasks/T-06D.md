# T-06D — journal-backed workflow attention bridge

Revision r7 · executable · optional host integration, admission remains disabled.

The existing attention RPC is backed by legacy escalation rows and in-memory continuations. Durable approvals must not be copied into that plaintext database or resolved through its deferred promises. Add a direct journal-backed attention service and an optional handler dependency. Merge authorized projections through existing LIST_ATTENTION; reserve durable: identities for exact durable decisions through RESOLVE_ATTENTION. Missing durable service, journal errors and invalid durable requests never fall back to legacy approval.

Trusted host actor resolution must verify current workspace access and return a stable principal matching the run. Transport clientId is only connection context and is not an authenticated principal. Freeze caller input before asynchronous authorization. Derive policy/account/digest from journal, never from renderer claims. Store the exact normalized review payload inside encrypted approval state; older records missing this payload cannot be approved through the bridge, but may be denied. Never expose credential identity or principal in the display DTO.

Decision requests carry command ID and expected version. Preserve duplicate receipts after lost replies and later controls. Journal commit is authority; RPC notifications are best-effort refresh hints. Reconnect rebuilds pending attention directly from the journal, so no cross-database atomicity or separate projection store is implied. The existing outbox remains journal-owned; broader event cursor/reconnect UX is P-05.

Renderer forwards stable per-action command identity/version across retries and accurately labels durable denial as stopping the workflow. Existing legacy API calls retain their contract. No redesign, no new public admission, no running app restart, no SessionManager/desktop host instantiation in this slice: production actor/key lifecycle and rollout remain gated.

Ownership: journal/attention owner edits approval payload persistence plus new durable-workflow-controls service/tests; RPC owner edits workflow-runs handler/dependency/tests; parent owns protocol DTO, renderer request forwarding, actual-host process evidence and packet. Rival is independent read-only; fixes remain authorized.

Acceptance: exact normalized payload and redaction; cross-workspace/principal rejection; async input mutation; stale/conflicting/duplicate decision handling; expired/missing-payload denial; lost notification after successful commit; reserved-ID failure closed; legacy coexistence. Actual Pi host crash recovery uses this bridge for persisted approval decision, then resumes with current policy revalidation. Run affected suites and shared/server-core/Pi/Electron typechecks, focused lint, copied packaged journal proof and independent review.

This sub-slice does not close T-06 control routing or P-03. Safe provider effects, children, schedules, migration and release certification remain separate tasks.
