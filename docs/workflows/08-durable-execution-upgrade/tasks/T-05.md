# T-05 — real Pi SDK checkpoint and replay integration

Revision r3 · P-02 · executable · depends T-04 agreed protocol.

Own shared PiAgent bridge and pi-agent-server checkpoint/controller. Wire actual awaited core-agent events, not AgentSession observers. Reconstruct from frozen context and replay recorded assistant/tool results through actual SDK loop; cached turns never call provider. Commit whole model turn before executing any tool and tool result before returning to SDK. Use stable logical turn/call identities, canonical transformed input and strict divergence checks.

Freeze native read/grep/find/ls capability set; check at every local and parent dispatch. No proxies, shell, browser, child, mini-model, dynamic registration, steering, branching, fallback, auto-compaction, SDK retries or speculative prefetch in this restricted route. Ordinary sessions retain behavior. Host-owned bridge is not a renderer authority field. Cancellation persists before abort; rejected/lost checkpoint must stop the entire durable run rather than become an ordinary recoverable tool error.

Validation: actual pinned Pi core SDK loop in fresh processes against journal/persistent fake provider, kill after assistant and first read result, exactly one provider call per recorded turn and one invocation per completed read. Test uncertified/dynamic tools, context/manifest drift, storage rejection, control fences, errors and disabled features. Typecheck shared/pi/server; build Pi bundle and packaged isolated Electron main proof without restarting user's app. Rival review then fix confirmed issues before acceptance.
