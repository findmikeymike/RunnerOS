# T-06C — ordered durable steering

Revision r6 · executable · internal certified read runner only.

Accept trusted host updates as encrypted ordered commands with command identity and expected version. Acknowledgement proves persistence; applied boundary and continuation revision prove delivery. Duplicate receipts must not enqueue twice or revive newer control state. Updates apply in command order, including across process death. Pause remains paused; Cancel remains terminal.

Use the actual Pi core awaited turn_end boundary, after the tool batch and before the next model turn; initial boundary is -1. Select and persist all pending updates, with deterministic SDK user messages. Selection may extend during replay only before the successor model reservation. A queued update arriving between selection and a new reservation blocks dispatch and triggers fresh replay. Once reserved, the original model input remains immutable. Complete cannot win over an already accepted queued update.

Supersede never-dispatched calls and invalidate their unused approvals, retaining an explicit skipped disposition. Check this before legacy pre-tool permission handling, then again before normalized dispatch. Already dispatched reads finish/recover under their original identity; completed results never change. Actual tool-result checkpoints still require an issued attempt. Steering cannot grant permission, widen tools, reset budgets or alter past prompts/results.
