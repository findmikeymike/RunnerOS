# T-06F — host startup and shutdown lifetime

Revision r9 · executable · one bounded P-03 task.

Provide a trusted host factory that loads the existing protected key, opens the journal and constructs the read runner plus controls service. Zero the temporary key after construction. Existing missing/locked/unavailable key protection must fail closed. Preserve journal identity on reopen; do not automatically execute recovered work.

Shutdown fences new requests synchronously, persists cooperative pauses for active running work, and drains accepted requests, executions, queued continuations and backend shutdown promises before closing storage. Pending binding/identity lookups cannot admit new execution after the fence. Late issued results may still save; queued resume and steering cannot start a replacement backend. Never force-close storage while work is pending. Report original shutdown/storage errors; permit a safe retry after a settled failure while keeping admission fenced.

Ownership: parent owns host factory/export/docs; runner worker owns quiesce and runner regressions; test worker owns host lifecycle tests. Rival performs independent read-only review; parent fixes meaningful findings.

Acceptance: protected-key fixture reopen; no implicit replay; missing/unavailable key refusal; immediate shutdown fence; active pause before drain; accepted async request drain; late result preservation; no replacement execution; hung/rejected abort handling; caller-input pinning; idempotence and safe close retry. Run affected durable journal/Pi/RPC suites and server typecheck.

Boundary: the factory is not registered in Electron bootstrap. Actual stable actor resolution, app quit integration, OS secure-storage certification and live UI activation remain separate tasks. Fixture envelopes do not prove operating-system protection. Existing actual Pi subprocess regressions exercise the runner, not this new host factory. No app restart, provider action or public admission.
