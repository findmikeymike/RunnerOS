# T-06E — explicit durable workflow controls

Revision r8 · executable · optional host service, no public admission.

Add a dedicated workflow-runs:durable-control RPC and Electron transport method for Pause, same-run Resume, Cancel and ordered steering. Never overload legacy Resume, which reruns a step using the current workflow definition. Durable commands must not fall back to legacy runners when identity, storage or configuration is unavailable.

Commands contain action, commandId and expectedVersion; steering alone includes text. Reject extra caller authority fields. Resolve current access and stable principal through the existing trusted host resolver. Require a matching persisted run principal; unbound historical read runs are not silently assigned to the current client. Freeze arguments before asynchronous authorization.

Extend the journal-backed service to return immutable command receipt separately from a redacted current state (status, version, control/continuation revisions and pending update count). No prompts, results, update text or credentials in this response. Exact duplicate commands acknowledge the stored receipt without repeating resume, abort or steering; newer controls remain authoritative. Journal lookup rejects conflicting reuse of command identity. New commands invoke the real durable runner; asynchronous continuation is tracked separately and does not delay command acknowledgement.

Ownership: journal/service owner owns receipt lookup and service/tests; RPC owner owns handler/dependency/tests and Electron API/channel-map exposure; parent owns protocol channel/routing/DTO and actual process probes/evidence. Independent rival reviews; meaningful fixes are authorized. Existing attention and legacy workflow behavior must stay covered.

Acceptance: all four controls, principal/workspace/CAS validation, rejected extra authority, mutation races, immutable duplicate acknowledgement after newer decisions, no blocking on whole-run completion and no legacy fallback. Actual host process test sends controls through the service, kills after persisted Pause/steering/Resume or Cancel, then uses the actual Pi runner to prove recovery or no further work. Run transport route/parity tests, affected suites/typechecks, copied packaged control journal proof and independent review.

The service remains an optional unconfigured production dependency. Host actor/key lifecycle, run-view projections and rollout remain separate work. This does not close T-06/P-03 or certify live UI. No app restart or push.
