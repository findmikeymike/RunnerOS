## Thin journey

A fixed fixture run records a model turn, waits on an exact approval, launches a required child, receives validated child output and calls a fake provider whose effect ledger survives app-worker death. A final output requires all preceding committed results. A separate unrelated run remains recoverable while the fake provider is unavailable.

Implement the smallest explicit continuation interpreter that proves this journey through the existing boundary contracts. Keep the provider simulator and crash controller in separate processes. Never persist JavaScript closures/Promises as the continuation.

## Required experiments

1. Kill after committed model turn and after first tool result: no model regeneration or repeated completed tool call.
2. Kill while awaiting approval, after approval storage, after child launch and after child result before parent join: original operation/child identity survives; decision and join are consumed once.
3. Provider accepts effect then drops response: idempotent variant reconciles to one effect; nonreplayable variant becomes unknown without resend.
4. Change canonical inputs/account/adapter version: strict divergence stop. Revoke permission while waiting in the same process: dispatch blocked.
5. Race cancel, duplicate delivery and stale owner completion: no successor after cancellation, no second child, no terminal resurrection.
6. Budget bound/deadline persists; an unavailable provider does not block unrelated recoverable work.

Compare the local journal candidate with a thin DBOS adapter on these exact contracts.
