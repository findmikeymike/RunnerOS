# P3: Verify and release

See [roadmap](../roadmap.md) for entry/exit behavior and [architecture](../architecture.md) for contracts. Dependencies and status are in plan.json. Tasks: T05, T06.

Entry review confirms the previous phase's evidence (if any), the latest main baseline, no overlapping unfinished work, and a viable path for assigned tools. Phase review is not a product approval dialog.

Exit evidence must contain revision, commands/procedures, actual assertions, mock/live boundary and reviewer. Preserve failures and later fixes in evidence rather than replacing failed results with a vague green claim. No automatic phase-end user permission request where existing implementation authorization covers the work.
